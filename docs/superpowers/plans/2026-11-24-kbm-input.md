# Keyboard + Mouse Input Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Play Skyward Sword HD start to finish on keyboard + mouse: mouse = camera and sword, WASD = movement, one action per key.

**Architecture:** The mouse becomes a virtual right stick inside `fill_state` (`runtime/hle/input.c`). A pure, header-only state machine (`runtime/hle/mouse_sword.h`, same style as `zr_tap.h`) turns motion + buttons into stick values and button pulses. The existing Free Camera path adds L for the camera. A keyboard preset fills `g_bind_key`.

**Tech Stack:** C (gnu11), SDL3, ImGui (`runtime/ui/*.mm`), Python wrappers for tests, GitHub Actions CI.

**Spec:** `docs/superpowers/specs/2026-11-24-kbm-input-design.md`

## Global Constraints

- Changes stay in `runtime/hle/input.c`, `runtime/hle/bindings.c`, `runtime/input_bind.h`, `runtime/settings.*`, `runtime/ui/controls_ui.mm`, plus the new `runtime/hle/mouse_sword.h` and `runtime/kbm_preset.h`. The game's Npad state layout is untouched.
- No gyro or Wii-pointer emulation. Sword direction = right stick (button-only scheme).
- No chord bindings (no Ctrl+RMB, Shift+E). Q stays the free-cam toggle (the existing short L tap).
- RMB presses ZL and R together while held (decided with the user).
- The existing "Keyboard" default preset stays; current users are unchanged unless they pick "Keyboard + Mouse".
- Scripted test runs ignore the real mouse (`input_user_blocked` already does; nothing new may bypass it).
- Every new input path is headless-testable like `tools/test_zr_tap.c`.
- **Deviation from the spec (my call):** rebinding mouse buttons through the capture UI is deferred. Mouse buttons are fixed actions in this plan. Keyboard slots stay rebindable. `mouse_*` settings default to off; the preset turns them on.

## Review Focus

- Menu opens or window loses focus while LMB / M4 is held: no stuck button, no pending flick, no stuck relative-mouse mode after returning.
- A huge motion delta (alt-tab, relative-mode toggle, warp) must not spin the camera or fling the aim.
- LMB with no recent mouse movement still swings (last direction, vertical by default), never silently drops the click.
- Slash flick must not be turned into camera by Free Camera's synthesized L, and aiming (M4) must not turn the camera either.
- Mouse enabled but Free Camera off, or a hand-edited `mouse_sens = nan` in the ini: no crash, no NaN reaching the game.

### Task 2: Mouse state machine

**Files:**
- Create: `runtime/hle/mouse_sword.h`
- Create: `tools/test_mouse_sword.c`, `tools/test_mouse_sword.py` (copy the compile/run wrapper of `tools/test_zr_tap.py`; no `-lm` needed, avoid libm)
- Modify: `.github/workflows/ci.yml` (add `python3 tools/test_mouse_sword.py` next to `test_zr_tap.py`, ci.yml ~line 110)

**Interfaces:**
- Produces, in `mouse_sword.h` (pure, single-threaded; the caller serializes motion and step with one mutex):
  ```c
  enum { MS_CAM_WINDOW_MS = 50, MS_SLASH_WINDOW_MS = 100, MS_FLICK_MS = 70, MS_THRUST_MS = 60,
         MS_MAX_DELTA = 200, MS_RING = 32 };       // all tunable (Task 7)
  typedef struct { bool lmb, mmb, rmb, aim; } MouseBtns;     // aim = M4 held
  typedef struct { bool camera, combat; float sens; } MouseCfg;
  typedef struct {
      int32_t rx, ry;        // virtual right stick, pad scale, up = +ry
      bool no_cam;           // flick or aim in flight: Free Camera must not add L
      bool rstick_click;     // thrust (MMB)
      bool zl, r;            // RMB
      bool use_item;         // LMB while aiming
  } MouseOut;
  typedef struct MouseSword MouseSword;   // ring of (ms,dx,dy), last dir, edge + timer state, aim position
  void mouse_sword_reset(MouseSword *m);
  void mouse_sword_motion(MouseSword *m, float dx, float dy, uint64_t now_ms);  // one SDL motion; each axis clamped to ±MS_MAX_DELTA
  MouseOut mouse_sword_step(MouseSword *m, MouseBtns b, MouseCfg c, uint64_t now_ms);
  ```

- [ ] **Step 1: Write the failing test** `tools/test_mouse_sword.c` (zero-init `MouseSword` is valid; helper `step(m, btns, cfg, t)` with cfg `{true,true,1.0f}`). Assertions:
  - Camera: `motion(100,0,t=0)`; step at t=10 → `rx==32767, ry==0, !no_cam`; step at t=200 → `rx==0`. `motion(0,-100)` → `ry==32767` (mouse up = stick up). `sens=0.5` with `motion(100,0)` at t=0, step t=10 → `rx` within ±1 of `16383`. `cfg.camera=false` → `rx==ry==0`.
  - Slash: after `motion(80,0,t=0)`, LMB press at t=50 → `rx==32767, ry==0, no_cam`; still `no_cam` at t=50+MS_FLICK_MS-1; at t=50+MS_FLICK_MS+1 with LMB still held → `!no_cam, rx==0` (no second flick until release + press). Directions: `(-80,0)`→rx −32767; `(0,80)`→ry −32767; `(70,-70)`→rx==ry==23170 (snap to 8 directions by comparing |dx| and |dy| against 0.4142, no atan2).
  - Click with no motion in the window (|sum| < 4 px): first click → `ry==32767, rx==0` (vertical default); after a right slash, a stationary click reuses right.
  - `cfg.combat=false`: LMB / MMB / RMB / aim do nothing.
  - Thrust: MMB press → `rstick_click` until MS_THRUST_MS passes, then false while still held; release + press fires again. RMB held → `zl && r`; released → both false.
  - Aim: with `aim`, `motion(150,0)` → `rx` within ±1 of `16383`, `ry==0`, `no_cam`, and the camera sum is NOT added; further motion clamps the vector to radius 32767; `motion(10000,0)` counts as 200 → `rx` within ±1 of `21844`; releasing aim → `rx==0`; LMB while aiming → `use_item==true` and no flick.
  - `mouse_sword_reset` then a click → vertical default again; no flick pending after a reset mid-swing.
- [ ] **Step 2:** Run `python3 tools/test_mouse_sword.py`. Expected: compile error (header missing).
- [ ] **Step 3:** Implement `mouse_sword.h` per the interface above. Camera stick = (sum of ring samples within MS_CAM_WINDOW_MS) / MS_CAM_WINDOW_MS px/ms ÷ 2.0 px/ms × 32767 × sens, clamped. Slash direction from the MS_SLASH_WINDOW_MS sum. Aim position accumulates delta × sens × 32767/300 and clamps by vector length.
- [ ] **Step 4:** Run `python3 tools/test_mouse_sword.py`. Expected: exit 0.
- [ ] **Step 5:** Commit `Mouse state machine: camera velocity, slash flick, thrust, aim`.

### Task 4: Wire the mouse into input.c

- Modify: `runtime/hle/input.c` (event switch ~line 419; `fill_state` ~735-872; `input_reset` ~236; `input_cursor_event` ~290), `runtime/nvn/vulkan/device.c` (event loop ~1350-1368), `runtime/nvn/metal.m` (same loop, macOS, untested here)

**Interfaces:**
- Consumes: `MouseSword`, `MouseBtns`, `MouseCfg`, `MouseOut` (Task 2); `g_settings.mouse_*` (Task 3); the "use item" slot and aim requirement from Task 1.
- Produces: `bool input_mouse_captured(void)` — true when `(mouse_camera || mouse_combat) && !menu_input_captured()`. The device loops call `SDL_SetWindowRelativeMouseMode(window, input_mouse_captured())` once per loop iteration, only on change.

- [ ] **Step 1:** In `input_handle_event`: on `SDL_EVENT_MOUSE_MOTION` call `mouse_sword_motion(&mouse, xrel, yrel, SDL_GetTicks())`; on `SDL_EVENT_MOUSE_BUTTON_DOWN/UP` update `MouseBtns` (`SDL_BUTTON_LEFT/MIDDLE/RIGHT/X1`); on `SDL_EVENT_WINDOW_FOCUS_LOST` and in `input_reset` clear buttons and call `mouse_sword_reset`. Guard all of it with one `pthread_mutex_t` shared with the `fill_state` step. If the loops do not forward window events to `input_handle_event`, add the focus-lost case where they do.
- [ ] **Step 2:** In `fill_state`, call `mouse_sword_step` once per poll (zero output when `menu`), add `mo.rx/mo.ry` into the `rx/ry` sums before the Free Camera block, OR `mo.zl/mo.r` into `b`, map `rstick_click` to `BTN_RSTICK` and `use_item` to the Task 1 slot, and add `|| mo.no_cam` to `synth_off`. If Task 1 says aiming needs ZL, also set it while `aim` is held.
- [ ] **Step 3:** `input_cursor_event`: when `input_mouse_captured()`, never `show` on mouse motion or button. Add the relative-mode toggle to both device loops.

- [ ] **Step 5:** Build, then run with `LARECOMP_HOST_INPUT='<frame>:mouse:80/0,<frame+5>:mouse:click'` and `LARECOMP_INPUT=1` (syntax: `docs/debug-hooks.md`). Expected log: a slash to the right. Also run `python3 tools/test_mouse_sword.py` and `python3 tools/test_zr_tap.py`.
